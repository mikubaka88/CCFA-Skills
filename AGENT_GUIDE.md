# Agent Guide

Use this guide when operating the CCFA family. Runtime skills and shared contracts remain authoritative; user instructions and host permissions take precedence.

## Family File Contract

Before file-producing work, resolve the canonical deliverable and one stable working directory per task/artifact. Reuse explicit paths and this artifact's established task folder; otherwise use project-root `ccfa-workfiles/<purpose>/<artifact-id>/`, such as `figures/method-overview` or `reviews/paper-short-title`. Create source/assets/cache/build subdirectories only as needed. Update current files in place, preserve required evidence, and remove only verified disposable files created by this task. A skill transition inherits these paths. Use UTF-8 text I/O and verify Chinese text in saved/rendered output. Follow [artifact-contracts.md](ccf-common/references/artifact-contracts.md); do not create working files for an inline answer without need.

## Routing And Cooperation

Before any CCFA specialist, activate `ccf-humanization` first, then `ccf-common`. Read and apply their entry rules even for review, retrieval, drawing, setup, or maintenance. Reuse applicable active rules across contributors; refresh them when changed or lost. Bootstrap once without recursive invocation. Detailed editing or maintenance workflows run only when relevant, and explicit user/host limits still apply.

1. Assign an integrating owner to each requested deliverable. Identify applicable prerequisites, reuse valid evidence, and actively involve specialists for missing inputs, material uncertainties, and affected completion checks using `ccf-common/references/routing.md`. Ownership is responsibility for integration, not isolated execution. Necessary collaboration needs no separate user request; preserve explicit scope limits and host permissions.
2. Read the owner and needed contributors' `SKILL.md` entries, then only relevant references. Use `ccf-common/references/skill-trigger-registry.yaml` for ambiguous routing and `ccf-common/references/handoff-modes.md` for evidence transfer, authorization, and integration. Avoid duplicate reports and retrieval; retain necessary evidence coverage.
3. Humanization's baseline applies throughout the family: communicate directly and preserve evidence, uncertainty, and rigorous criticism. Its sentence-editing procedure applies to authorized prose work. Review-only tasks do not rewrite assessed text, and non-prose work creates no text merely to run a check. Avoid duplicate preflight reports and warning appendices.
4. Read existing `ccfa.yaml` when project state matters. Reuse canonical artifacts and `ccf-common/references/artifact-contracts.md`; do not create process files for a paragraph edit. `ccf-project-scaffolder` may initialize missing project state when setup is requested.
5. Use `ccf-paper-writer` for drafts, revisions, compression, and presentation prose. Preserve the requested Markdown/LaTeX structure. For a full submission manuscript, load the applicable venue and length guidance; use the existing NeurIPS fallback when appropriate. Fill scientific gaps from supplied material, mark missing evidence `TBD`, and stop expansion when it would require filler or invention.
6. Use `ccf-idea-optimizer` for developing or rescuing an idea. Use `ccf-idea-reviewer` for judging value, novelty, or mechanism, including “靠谱吗” and “值得做吗” without scores. A full PDF can still be input to concept-only review; experiments stay outside that scope unless requested. Closest-work overlap needs a concrete mechanism comparison and evidence basis.
7. Use `ccf-literature-monitor` for new-paper and competitor tracking, `ccf-literature-searcher` for external literature or benchmark discovery, and `ccf-integrity-auditor` for existing citation and claim-support checks. Distinguish a one-time report from a scheduled monitor.
8. Keep datasets, baselines, metrics, ablations, result schemas, and chart evidence with `ccf-experiment-designer`. Full-method identity checks apply to reported comparisons; cited methods and proposed designs use their relevant sources. Legitimate labeled ablations remain valid.
9. Use `ccf-visual-composer` for figure/table rendering, layout, palettes, method diagrams, editable reconstruction, and render QA. Continue requested image generation and editable formats under existing authorization. Offer an optional reconstruction only when it was not requested. Honor explicit pure SVG and do not label an embedded raster as editable.
10. Use `ccf-paper-to-exemplar` for supplied PDF writing patterns. Preserve extraction provenance and register an exemplar only when requested; do not treat an unfilled card as completed analysis. Reading one paper closely to understand its reasoning and evidence boundary belongs to `ccf-paper-xray`; that reading reports what the paper does and how far its evidence reaches, and never a verdict, score, or novelty judgement.
11. Use `ccf-paper-reviewer` for assessment without rewriting, including cross-version comparisons. Separate relative progress from absolute readiness and trace score decreases to evidence under a frozen contract. Independent reviewers require separate permitted calls; otherwise label single-agent role perspectives honestly.
12. Use `ccf-submission-checker` for current venue/year/track rules and actual LaTeX/PDF/package checks. Distinguish passed, failed, not applicable, and unverified. Checking readiness does not authorize submission.
13. Use `ccf-rebuttal-writer` for requested author responses, revision ledgers, and resubmission plans. Evidence-backed responses and explicitly requested manuscript revisions may proceed together under their respective owners.
14. Use `ccf-pipeline-orchestrator` for planning or dependency coordination that materially helps completion; ordinary collaboration needs no extra coordinator. `ccf-common` owns shared policy; `ccf-skill-forger` maintains the family and documentation diagrams. Integrate contributions, resolve conflicts, and verify affected results. Reopen changed dependencies; preserve valid completed work. Finish only when applicable prerequisites and requested outputs/checks are complete, or identify the dependent result that remains incomplete.
15. Follow `ccf-common/references/task-modes.md` for selective context, mid-task steering, permitted delegation, and proportionate verification. Keep model settings in the host and retain current official provenance in the existing source registry.

Existing editable visuals use direct source edits and affected exports. Handoffs carry scope, prerequisite status, source versions/anchors, canonical paths, and a concrete question/completion condition. Internal specialist checks return findings to the owner; user-requested reviews retain their full templates. A failed build must not replace a usable artifact or be reported as a successful refresh.
