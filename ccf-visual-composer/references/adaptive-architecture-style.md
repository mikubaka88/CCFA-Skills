# Optional Diagram Treatments

Read this only when the user's prompt/reference leaves a genuine illustration or visual-treatment choice. The scientific understanding and P → G0 → G1 workflow live in [architecture-diagram-generation.md](architecture-diagram-generation.md); this file adds no generation stage, coordinate plan or compulsory preset.

## Choose From The Actual Mechanism

Let the topology guide composition: sequential transformations can use one aligned path; real parallel branches merge at their integration point; graphs/memory retain their node/edge meanings; iterative methods show the state, loop direction and exit relation when supplied. Concrete frames, masks, tokens, trajectories or state snapshots should explain a named operation, not decorate empty space.

Give the decisive transformation more emphasis than generic encoders or output heads. Matched baseline/proposed or train/inference comparisons can align shared objects and isolate the actual difference. Use a compact problem-to-mechanism cue only when the figure's purpose calls for it. These are visual goals for the image model, not instructions to author boxes, ports or geometry.

## Coordinated Presets

Use a preset only if it helps an unresolved choice. A supplied inspected reference and explicit font/color choices take precedence. Keep an approved treatment in local edits; do not rotate it during refinement. Include only the selected colors and relevant appearance in P, not this whole menu. Fonts below are starting choices subject to the actual user/destination requirement.

| Preset | Scientific representation | Type and treatment | Palette starting point |
| --- | --- | --- | --- |
| `formal-roman` | Compact operators and an open computation graph, with the decisive transformation clear. | Times New Roman, bold group headings, subordinate labels and clean restrained connections. | `ccfa_ink`, dark context and a stable contribution accent. |
| `soft-mechanism` | Concrete tensors, tokens, graphs or objects, with detail near its operation. | Times New Roman, light semantic grouping and restrained shading inside illustrations. | `ccfa_ceramic`, teal/terracotta with light warm fills. |
| `visual-evidence` | Matched image strips/crops, modality lanes and a compact mechanism region. | Times New Roman, consistent crop identity, label baselines and light overlays. | `ccfa_arctic` or `ccfa_gem`. |
| `geometric-flow` | Actual spatial structures, trajectories or supported continuous transformations. | Times New Roman with compatible math, shared viewpoint and a clear foreground transformation. | `ccfa_nocturne` or `ccfa_ceramic`. |
| `compact-comic` | Recognizable simplified scientific objects in compact aligned groups. | Comic Sans MS with legible math, coherent object scale and clear connections. | `ccfa_orchid` or `ccfa_ceramic`. |

Palette values and shared role rules are in [palette-and-accessibility.md](palette-and-accessibility.md). Titles, legends and quantitative axes retain their requested boldness and final-size hierarchy. Method body labels do not all need heading weight. Numerical plots can reuse compatible colors/type but retain code-generated marks and their selected specification; a visual treatment does not create a distribution, field or experimental result.

## Destination Context

A paper mechanism figure benefits from an economical scientific path, recognizable representations, concise labels and compact grouping. A slide/poster may need larger type and explanatory callouts; README/outreach may need an overview metaphor. Use the actual requested purpose rather than labeling every graphic a computation graph or forbidding useful conceptual overviews.

Conference/field associations can guide an open design choice, but are not official styles: image/video work often benefits from matched visual strips; language work from token/example alignment; spatial methods from grounded geometric objects; systems work from meaningful interfaces and boundaries. An informal/comic treatment follows the user's choice or actual reference, not a conference name. Verify venue rules only when they affect the requested deliverable.

## Reference And Source Boundary

Use the reference's actual composition, object treatment and type hierarchy without transferring unrelated scientific labels or claims. Keep method names and outward titles functional. Preserve attribution/credits in the current source record; reference-workflow provenance remains registered as `astradraw-visual-workflow` in Common's source registry. Do not import its component pack, scripts or asset library by default. Use only authorized relevant images within the current privacy boundary.
